# UncensoredAI — любая uncensored-модель с Hugging Face на GPU-сервере Clore.ai

> **In English.** A local, dependency-free UI (Python stdlib only) that rents a GPU server on
> [Clore.ai](https://clore.ai/register?ref_id=hwiqaztv) and deploys any uncensored model from Hugging Face in one click.
> It picks the engine from the weight format (GGUF → llama.cpp, safetensors/AWQ/GPTQ/FP8 → vLLM,
> EXL3/EXL2 → TabbyAPI), estimates VRAM from the model's own `config.json`, finds the cheapest
> suitable server, waits for the build and download with live progress, then exposes an
> OpenAI-compatible endpoint and points OpenCode at it. Bad hosts (silent after five minutes,
> or downloading at less than half the advertised speed) are dropped and blacklisted
> automatically. Runs on Windows, macOS and Linux. The rest of this README is in Russian.

Локальный UI: выбираете расцензуренную модель из подборки Hugging Face (или вставляете свою ссылку),
вводите API-ключ [Clore.ai](https://clore.ai/register?ref_id=hwiqaztv), жмёте «Арендовать и развернуть» — получаете
OpenAI-совместимый endpoint с вашим ключом и переключённый на него OpenCode.

Движок подбирается по формату весов автоматически:

| Формат весов в репозитории | Движок | Docker-образ |
|---|---|---|
| EXL3 / EXL2 | TabbyAPI (ExLlamaV3) | `nvidia/cuda:12.8.1-runtime-ubuntu24.04` |
| GGUF | llama.cpp server (сборка с CUDA) | `nvidia/cuda:12.8.1-devel-ubuntu24.04` |
| safetensors, AWQ, GPTQ, FP8 | vLLM | `nvidia/cuda:12.8.1-runtime-ubuntu24.04` |

Все три отдают один и тот же API: `http://<host>:<port>/v1`, модель называется `uncensored`,
авторизация — `Authorization: Bearer <API_KEY>`.

**GGUF или не-GGUF.** `safetensors` — исходные веса от автора: полный размер (Qwen3.8-Flash-Next
в bf16 это 335 ГиБ), только в VRAM и целиком, зато быстрее на параллельных запросах. `GGUF` —
формат llama.cpp: веса квантованы (та же модель в Q4_K_XL — 104 ГиБ), кванты лежат в одном
репозитории, и часть весов можно держать в обычной оперативке. Короткое правило: safetensors —
когда VRAM хватает и нужна скорость, GGUF — когда VRAM мало, а модель большая. Полное сравнение
со всеми последствиями выбора — в UI на вкладке «Модель», блок «Что такое GGUF и не-GGUF».

Вызовы инструментов включены во всех трёх движках: llama.cpp стартует с `--jinja`,
vLLM — с `--tool-call-parser` под семейство модели (`qwen3_coder`, `mistral`, `deepseek_v3`,
`glm45`, `kimi_k2`, иначе `hermes`). Если собранная версия vLLM такого парсера не знает,
startup-скрипт сам откатывается на `hermes`.

## Быстрый старт
1. Запустите UI — откроется http://127.0.0.1:8765. Нужен только Python 3.9+, внешних пакетов нет.

   | система | команда |
   |---|---|
   | Windows | `ui.bat` |
   | macOS, Linux | `./ui.sh` (один раз `chmod +x *.sh`) |
   | любая | `python3 app.py` |

2. Вкладка **Настройки**: вставьте `API-ключ Clore.ai` ([кабинет Clore](https://clore.ai/register?ref_id=hwiqaztv) → Settings → API),
   нажмите «сгенерировать» для ключа вашего API, при желании добавьте HF-токен и Telegram. «Сохранить».
3. Вкладка **Модель**: подборка актуальных uncensored-моделей (uncensored / abliterated / unfiltered /
   amoral / heretic / dolphin …) с панелью периодов и фильтром по формату, либо своя ссылка —
   `https://huggingface.co/owner/name` или просто `owner/name`. «Выбрать» → UI покажет формат, движок,
   размер весов, оценку нужной VRAM и диска.
4. Вкладка **Сервер**: «Найти серверы» — маркетплейс Clore, уже отфильтрованный под требования модели.
   Можно выбрать конкретный сервер или оставить автоподбор (самый выгодный с учётом скорости канала).
5. Вкладка **Деплой**: «Проверить без аренды» покажет кандидатов, «Арендовать и развернуть» создаёт
   заказ и ведёт лог до строки «модель готова».

Подъём с нуля: 10–40 мин (в основном скачивание весов; для GGUF плюс сборка llama.cpp).

### Откуда берётся «нужно VRAM»
`веса выбранного кванта + KV-кэш под контекст + буферы движка`.

Буферы движка — `1 ГиБ + буфер логитов + 5% весов`, не больше 12. Буфер логитов это
`vocab × 512 × 4 байта`: у Qwen3.8 словарь 248 320 токенов, и он один занимает 0.47 ГиБ.
Прежняя формула (`1.5 ГиБ + 2% весов`) давала 1.8–1.9 ГиБ на модели 16–22 ГиБ и не
учитывала ни CUDA-контекст, ни логиты — модель на 20 ГиБ проходила на карту с ровно
20 ГиБ и падала по OOM.

Это оценка «сколько займёт». При подборе сервера к ней добавляется **`VRAM_HEADROOM`
= 10%**: карта «ровно под размер» не оставляет права на ошибку в оценке, а у vLLM ещё и
`--gpu-memory-utilization 0.92` — модель обязана уложиться в 92% карты.

KV-кэш считается не на глаз, а по `config.json` модели — своего у GGUF-репозитория нет,
поэтому он берётся у исходной модели из `base_model`. Наивная формула «слои × головы ×
head_dim» на современных архитектурах завышает в разы, и учитываются две поправки:

- **MLA** (`kv_lora_rank`, как у DeepSeek и GLM-5) — в кэш идёт сжатое латентное
  представление, а не полные K и V;
- **гибридное внимание** (`layer_types`) — у линейных слоёв состояние постоянное
  и от длины контекста не растёт.

Для GLM-5.3 Flash разница наглядная: по наивной формуле выходило 22.5 ГиБ KV, по факту — 0.2 ГиБ.
Если `config.json` недоступен (базовый репозиторий удалили), KV прикидывается по числу
параметров, и в карточке это подписано как «оценка».

llama.cpp запускается с кэшем в `q8_0` — это вдвое меньше fp16 при практически той же
точности; vLLM оставлен в fp16.

### Контекст
По умолчанию берётся **нативный контекст модели** из `max_position_embeddings`, но не
больше `CTX_CAP` = 131072: у свежих Qwen заявлены 262k, а с YaRN и до 1M, и на полном
контексте KV-кэш требует больше VRAM, чем сама модель. Настоящий потолок показан в
карточке модели («модель умеет 262k»), поле «контекст» принимает любое значение и
пересчитывает VRAM с серверами сразу.

Отдельно контекст подгоняется под **фактическую карту** уже после выбора сервера
(`hfmodels.ctx_for_vram`): контекст задают до аренды, и 262144 на 24-гиговой карте
раньше означали OOM через полчаса после начала скачивания весов. Теперь он делится
вдвое до того, что реально поднимется, и об этом пишется в лог.

> Раньше здесь была функция `_max_ctx`, которая спрашивала у HF API поле
> `config.tokenizer_config.max_position_embeddings`. Такого поля HF не отдаёт ни у одного
> репозитория — в блоке `config` только `architectures`, `model_type`, `chat_template_jinja`
> и имена спецтокенов. Функция всегда возвращала `None`, и каждый деплой молча уезжал на
> 32768 вместо нативных 262144.

### Галочка «эксперты в RAM»
У MoE-модели почти весь вес — это эксперты, а на токен работает малая их часть. llama.cpp
умеет держать их в обычной оперативке (`--n-cpu-moe`), и тогда карта нужна в разы скромнее:
у Qwen3.8-Flash-Next на экспертов приходится 97.6% веса, так что вместо 112 ГиБ VRAM нужно
**5.6 ГиБ VRAM и 127 ГБ RAM**. Галочка на вкладке «Сервер» показывается только когда режим
применим — MoE плюс GGUF (движок `llama.cpp`); у safetensors такого нет.

Выгружается **минимум необходимого** (`hfmodels.cpu_moe_layers`), и считается по объёму
*одной* карты, а не суммарному: llama.cpp кладёт оставшиеся на GPU слои подряд, то есть
на одно устройство.

Платим скоростью, и платит её CPU — поэтому в этом режиме меняется и подбор сервера.
Цена приводится «к токену» через число каналов памяти (`4.0 / ram_channels`): EPYC и Xeon
Scalable — 8 каналов, Xeon E5 — 4, десктопные — 2. Восьмиканальный хост за $0.138/ч
обгоняет четырёхканальный за $0.098/ч, потому что выдаёт примерно вдвое больше токенов.

> Этот пересчёт работал только в `deploy.py`. В UI `/api/offers` флага не получал,
> `ram_factor` оставался `1.0`, и список показывал «лучшую цену» на двухканальном
> десктопе, пока автоподбор при аренде брал восьмиканальный EPYC — список и деплой
> расходились на ровном месте.

### «💻 Экономные»
Подборка небольших моделей для домашнего ПК (`hfmodels.TOP_ECONOMY`), разложенная по
объёму видеопамяти: до 4 ГБ и без видеокарты, 6–8 ГБ, 12–16 ГБ, «8–16 ГБ + 32 ГБ оперативки»
(модели с экспертами в оперативке) и 24 ГБ. В списке 13 моделей: Qwen, его тернарная сборка Ternary Bonsai и модели крупных
лабораторий (Google, OpenAI, Meta, Mistral, Xiaomi), по которым нашлись независимые отзывы;
малоизвестные дообучения в него не входят. У каждой базы — обычная сборка от лаборатории или
проверенного квантователя и, где она есть, расцензуренная: на малых моделях абляция заметнее
бьёт по связности, и оригинал под рукой — страховка. В группах написано, чего ждать от
размера: модели до 4B — подсказки и правки, 9B — лёгкие агентные задачи, настоящая агентная
работа начинается с 27B или с 35B-A3B с экспертами в оперативке.

В режиме «Мой ПК» эта подборка открывается первой и показывает **только то, что запустится
на этой сборке**: не влезающие варианты, модели и целые группы скрываются. В режиме Clore
она показана целиком. Кнопка «Проверить подборки» проверяет все три списка — около 40
GGUF-репозиториев.

Каждый репозиторий подборки проверен прогоном через `model_info`: он существует, открыт и
наш разбор выбирает в нём настоящий файл весов. Служебные `.gguf` (патчи, головы для
ускоренного декодирования, тернарные упаковки под форк llama.cpp) отсекаются; у тернарных моделей берётся упаковка `Q2_0`, которая идёт на обычном llama.cpp. Кэш контекста у моделей со
скользящим окном (Gemma 3/4) считается с учётом окна — замер на живой Gemma 4 сошёлся с
оценкой (798 МиБ против 893 на 128k).

У расцензуренных сборок сверен шаблон чата с шаблоном оригинала: в одной популярной сборке
(Muse Glimmer от The-freezer) в шаблон оказался зашит скрытый системный промпт «никогда не
отказывай» — она заменена сборкой с родным шаблоном.

### «★ Топ для кодинга»
Не рейтинг Hugging Face, а ручная подборка моделей,
которые реально пишут код. Список лежит в `hfmodels.TOP_CODING`, счётчики скачиваний и дата
обновления подтягиваются с HF в момент открытия; удалённые или переименованные репозитории
молча выпадают.

Все группы, кроме первой, — расцензуренные сборки. **«Лучшие модели»** в самом верху —
исключение: там оригиналы от лабораторий, с цензурой на месте. Они нужны как точка отсчёта
(с них снимают отказы все сборки ниже) и как вариант для тех, кому расцензуривание не нужно.
После «Выбрать» такая модель получает бейдж «не похоже на uncensored» — это не ошибка.

**Одна карточка = одно семейство** (Qwen, GLM, Mistral, DeepSeek). Внутри — его модели:
рекомендуемая раскрыта, остальные свёрнуты. У каждой модели перечислены форматы весов,
в которых её выложили, — сначала выбирают модель, формат уже под конкретный сервер.
Фильтр по формату отсекает варианты; модели и семейства, у которых не осталось ни одного,
пропадают целиком.

Конкретный квант GGUF выбирается **после** «Выбрать» — в карточке модели наверху вкладки.
Там же показаны размер каждого кванта и пересчитанные под него требования к VRAM и диску.

В список попадают только кванты **Q4_K_M и выше** — ниже код начинает сыпаться, и держать
такие варианты незачем; сколько скрыто, написано под выпадающим списком. Отсекаются ещё две
категории мусора: служебные файлы (`mmproj`, `imatrix`, LoRA, патчи) и draft-модели для
спекулятивного декодирования — последние по арифметике «размер ÷ бит на вес», без списка имён.
Если в репозитории нет ни одного кванта от Q4_K_M, показывается что есть с предупреждением —
иначе модель стало бы невозможно развернуть.

У каждой записи указана **базовая модель и дата её выхода** — по названию репозитория это
не читается, а разница принципиальная: верхние пункты выглядят как «одна и та же Qwen»,
но стоят на базах 2026-08, 2026-01 и 2025-07.

| Семейство | Модели внутри |
|---|---|
| **Лучшие модели** — с цензурой | **Qwen3.8-Flash-Next** (Qwen, MoE 125B/6B актив., база 2026-08): контекст 262k, до 1M с YaRN, отказы не снимали. В двух форматах: официальный BF16 — 335 ГиБ, 8 карт по 48 ГБ под vLLM; GGUF от unsloth — UD-IQ4_XS 87 ГиБ / UD-Q4_K_XL 104 ГиБ, и к нему применима выгрузка экспертов (5–6 ГиБ VRAM + 108–127 ГБ RAM) |
| **Qwen** — основной выбор | **Qwen3.8-Flash-Next abliterated** (база 2026-08, UD-IQ4_XS 87 ГиБ / UD-Q4_K_XL 104 ГиБ) — рекомендуем: 97.6% веса — эксперты, с выгрузкой в RAM на карте остаётся 5–6 ГиБ; Qwen3.8-27B NEO-CODER-MAX (база 2026-08, Q4_K_M 16.8 ГиБ) — всё в VRAM, скорость не зависит от оперативки; Qwen3-Coder-Next (база 2026-01, Q4_K_M 45 ГиБ) — потолок качества; Qwen3.8-27B Coder390 EfficientThink — reasoning; Qwen3-Coder-30B-A3B (база 2025-07) — быстрая и дешёвая; Qwen2.5-Coder-14B (Q4_K_M 8.4 ГиБ) — дешёвый вход; Qwen2.5-Coder-32B — классика |
| **GLM** — универсал | GLM-5.3 Flash: не кодер по профилю, но пишет код на уровне топовых и держит длинный диалог, контекст до 1M. Кванты крупные (UD-IQ4_XS 146 ГиБ, UD-Q4_K_XL 186), но 98.1% веса — эксперты: с выгрузкой в RAM хватает 4.9–6.5 ГиБ VRAM и 177–269 ГБ оперативки |
| **Mistral / Devstral** — агентный | Devstral Small 2 24B: 65.8% SWE-bench Verified при 24B, плотная — предсказуема на длинных правках |
| **DeepSeek** — самое дорогое | **DeepSeek V4.1 Flash** (база 2026-10): Q4_K_M 397 ГиБ, FP8 475 ГиБ — 8 карт по 80 ГБ либо 18.3 ГиБ VRAM и 468 ГБ RAM с выгрузкой экспертов; **V4 Flash 0731**: Q4_K 153 ГиБ, 4 карты по 48 ГБ либо 14.4 ГиБ VRAM и 181 ГБ RAM — подъёмный вариант, если нужен именно DeepSeek |

Правило по квантам для кода: **не ниже Q4_K_M**. Ниже заметно падает точность генерации —
модель начинает терять скобки и отступы, и сэкономленные гигабайты обходятся дороже.
Этот же порядок зашит в выбор кванта по умолчанию (`_QUANT_RANK` в `hfmodels.py`): берётся
Q4_K_M, а при одинаковом имени — файл покрупнее, чтобы не подхватить draft-модель.

Подборку правьте прямо в `TOP_CODING` — UI подхватит после перезапуска `app.py`.

### Панель периодов на вкладке «Модель»
| Кнопка | Чем сортирует | Точность |
|---|---|---|
| За всё время | `downloadsAllTime` (сортировка на нашей стороне — HF не принимает такой `sort`) | точный счётчик |
| За месяц | `downloads` — счётчик Hugging Face за 30 дней | точный счётчик |
| За неделю | `trendingScore` среди моделей, обновлённых за 7 дней | приближение |
| За день | `trendingScore` среди моделей, обновлённых за 2 дня | приближение |
| Новые | `lastModified` | точно |

Недельных и дневных счётчиков скачиваний Hugging Face не публикует, поэтому «за неделю» и «за день» —
это рейтинг тренда HF среди свежих репозиториев; в UI это подписано под панелью.

## Режим «Мой ПК»
Переключатель **☁ Сервер Clore / 🖥 Мой ПК** в шапке (или ссылка `/#pc`) показывает, какие
модели поднимутся на компьютере, где запущен UI, — без аренды сервера.

- **Железо определяется на месте**, у каждого пользователя своё: NVIDIA — через `nvidia-smi`,
  AMD/Intel — через реестр Windows (64-битный объём, а не обрезанный до 4 ГБ из WMI) или
  sysfs на Linux, Apple Silicon — как общая память (модели отдаётся около двух третей).
  Встроенная графика не считается. Ошиблось — поправка на вкладке «Мой ПК»
  (`PC_VRAM_GB` / `PC_RAM_GB` в `.env`).
- **Из найденного вычитается резерв**: видеопамять, занятая прямо сейчас (рабочий стол,
  браузер; не меньше 1 ГиБ и не больше трети карты), и 12% оперативки, но не меньше 6 ГиБ.
  Память, занятая уже запущенной здесь моделью, в резерв не входит.
- **Оценивается только GGUF**: локально модель запускает llama.cpp. Для каждого кванта
  ищется лучший режим — целиком в видеокарте → эксперты в RAM (`--n-cpu-moe`, только
  MoE) → часть слоёв в RAM (`-ngl`) → только процессор. Не влезает на полном
  контексте — контекст делится вдвое, но не ниже 16k. Режим важнее контекста.
- **Квант**: если модель целиком влезает в карту, берётся самый точный из влезающих
  (до Q8_0) — иначе свободная VRAM просто простаивает. В медленных режимах — Q4_K_M,
  а контекст ограничен 32k: каждый гигабайт KV там отнимает слои у видеокарты.
- Отметки появляются в подборках, в поиске и в карточке модели (таблица по всем квантам
  с флагами llama.cpp); кнопка «Проверить подборки» раскладывает все GGUF-сборки по режимам.

### Запуск на своём ПК и как он защищён
Кнопка «Поставить на этот ПК» в карточке модели скачивает llama.cpp и выбранный квант,
проверяет их и поднимает `llama-server` на `127.0.0.1` с ключом из `api.key` (создаётся
один раз). Файлы — в `%LOCALAPPDATA%\UncensoredAI` (Linux: `~/.local/share/UncensoredAI`),
другой каталог задаётся строкой `LOCAL_DIR=` в `.env` (в UI такого поля нет). Модель работает
и после закрытия UI; остановить — кнопкой на вкладке «Мой ПК». Для каждого запуска нужен
интернет: софт сверяет версию llama.cpp и файлы модели. Обрыв связи посреди скачивания
не страшен — докачка продолжается сама. OpenCode переключается на неё отдельной кнопкой (провайдер «… (мой ПК)»).

GGUF — это веса, а не программа: при загрузке из файла ничего не исполняется. Защита
выстроена против того, что реально бывает:
- **Подмена при скачивании.** llama.cpp — только из релизов `ggml-org/llama.cpp` на GitHub,
  стабильная сборка (релиз `v*` указывает на ночную `b*` в `nightly-tag.txt`), со сверкой
  SHA-256 из API GitHub. CUDA-сборка подбирается под драйвер (совместимость внутри
  мажорной версии) и карту (Blackwell требует CUDA 12.8+). Из репозитория модели
  качаются только `.gguf` выбранного кванта — на зафиксированном коммите и со сверкой
  SHA-256 из Hugging Face. Скрипты и прочие файлы репозитория не скачиваются.
- **Испорченный GGUF, бьющий в загрузчик.** Заголовок разбирается на Python до запуска:
  длины строк и массивов, вложенные массивы, число измерений, смещения тензоров — всё
  против размера файла (`gguf_check`).
- **Если всё же прорвалось** — режим «Обычный», только на Windows (на Linux и macOS он
  прав не ограничивает, там для изоляции нужен Docker): `llama-server` с
  уровнем целостности **Low** (метка на exe) — писать в профиль, реестр и автозагрузку
  он не может; в **Job Object** — дочерние процессы запрещены, буфер обмена и рабочий
  стол закрыты; окружение без ключей и токенов. Проверено: процесс в той же изоляции не
  смог записать в «Документы», автозагрузку и HKCU и не смог запустить `whoami`. Что
  получил процесс на деле, UI показывает (уровень целостности, Job Object). Читать файлы
  Low-процесс может, поэтому есть кнопка «Закрыть ему интернет» — правило брандмауэра
  на исходящие (через UAC).
- **Режим Docker** — образ `ghcr.io/ggml-org/llama.cpp:server-cuda*`, закреплённый по
  digest, контейнер `--read-only`, `--cap-drop ALL`, `no-new-privileges`, модель
  смонтирована только на чтение, порт — только `127.0.0.1`. Нужен Docker Desktop (WSL2).
- **Не покрывается — поведение модели.** Если OpenCode разрешено выполнять команды без
  подтверждения, вредную команду выполнит он сам — где бы ни работала модель. Это
  настраивается в OpenCode (`permission`).

Локальная модель всегда слушает `127.0.0.1:8737` (если порт свободен), ключ создаётся
один раз и лежит в `api.key` в каталоге данных — поэтому прописанные OpenCode и Claude
переживают перезапуск без повторного нажатия кнопки. После смены модели нажмите кнопку
ещё раз: в лаунчере Claude и в конфиге OpenCode записаны название и контекст модели. То же,
если порт 8737 оказался занят и сервер поднялся на другом — номер порта виден в логе.

## Claude Code и Claude Desktop

Кроме OpenCode модель (с Clore или с этого ПК) можно отдать Claude — кнопки «Claude Code»
и «Claude Desktop» рядом с «Прописать в OpenCode». Claude говорит только на протоколе
Anthropic (`/v1/messages`): его отдают llama.cpp и vLLM, а TabbyAPI (EXL2/EXL3) — нет.

- **Claude Code** — кнопка создаёт команду `claude-uncensored` рядом с `claude` (в PATH).
  Она выставляет `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, модель `uncensored` для всех
  алиасов и реальный размер контекста (`CLAUDE_CODE_MAX_CONTEXT_TOKENS`) — только для своего
  запуска. Обычный `claude` и `~/.claude/settings.json` не меняются. Нужен контекст от 32k:
  одни инструкции Claude Code — около 19 тыс. токенов.
- **Claude Desktop** — кнопка прописывает модель в режим стороннего провайдера (Claude Desktop
  on 3P): отдельная запись `UncensoredAI` в `%LOCALAPPDATA%\Claude-3p\configLibrary` — то же,
  что пишет его окно Developer → Configure Third-Party Inference. Ваши записи там не трогаются,
  прежний `_meta.json` сохраняется рядом (`.before-uncensoredai`). После этого Desktop надо
  полностью закрыть (☰ → File → Exit) и открыть; на экране входа — вход через стороннего
  провайдера. Это отдельный режим со своей историей; вернуться — вход через Anthropic или
  кнопка «Убрать из Claude Desktop». Окно контекста незнакомой модели Desktop считает равным
  200 тыс. — задать меньше он не даёт, так что длинный разговор упрётся в контекст модели.

Anthropic официально не поддерживает Claude с не-Claude моделями: базовые вещи работают,
но вызовы инструментов у слабых моделей бывают кривыми.

## Важно про Clore.ai
- **Все цены в UI — в долларах за час.** Сам Clore публикует их за сутки и в трёх валютах
  (USDC / BTC / CLORE), поэтому UI пересчитывает: берёт USD-цену хоста (`price.original_usd`),
  а если её нет — конвертирует по курсам `currency_rates_in_usd`, и делит на 24.
- Валюта списания выбирается автоматически: самая дешёвая по курсу из тех, на которых есть средства.
  Принудительно задать можно флагом `--currency bitcoin|CLORE-Blockchain|USD-Blockchain`.
- Баланс и адреса депозита — вкладка **Заказы**.
- Типы заказа: `on-demand` (стабильно) и `spot` (дешевле, но ваш заказ могут перебить ставкой).
- **Сервер можно выбрать не один, а очередью** — до 10 штук кнопкой «В очередь» на вкладке
  «Сервер». Деплой идёт по ней сверху вниз: сервер успели арендовать, Clore не выдал адрес
  или контейнер молчит пять минут — берётся следующий, а молчавший отправляется в чёрный
  список. Ничего не выбрано — кандидатов (5 штук) подберёт автоподбор. Очередь
  останавливается, только чтобы не платить за два сервера сразу (негодный заказ не удалось
  отменить — номер остаётся в `.env`) или когда вы сами остановили деплой. Если движок упал
  уже на скачанных весах, очередь тоже встаёт: дело, скорее всего, в модели или контексте.
  То же, если установка упала с ошибкой на двух серверах подряд — причина явно не в них.
- **Деплой не арендует сервер поверх забытого заказа.** Если в `.env` остался заказ, который
  ещё оплачивается, но не отвечает (прошлый деплой прервали, движок упал), новый деплой
  останавливается и называет его номер — раньше он молча брал ещё один сервер, а ссылка на
  старый терялась. Погашенные заказы из `.env` убираются сами. Закрытая (gated) модель без
  `HF_TOKEN` тоже отклоняется до аренды.
- **«Остановить деплой»** отменяет только те заказы, которые арендовал этот деплой, — в том
  числе создававшийся в момент нажатия. Сервер, работавший до него, не трогается.
- **Зависший сервер отменяется через 5 минут.** Застой меряется не строкой прогресса, а
  «пульсом» контейнера: скачанные байты, рост логов установки, занятая видеопамять и
  процессорное время. Сборка llama.cpp, `pip install` и загрузка весов в VRAM длятся по
  10+ минут без смены стадии и порой без единой строки в логе, но процессор при этом
  занят, а 5 минут полной тишины — это зависание. Потеря связи с вашей стороны застоем не
  считается; сервер отменяется, только если не отвечает на опросы 20 минут подряд. Если
  установочный скрипт сам завершился ошибкой, деплой узнаёт об этом сразу, а фоновое
  скачивание весов прекращается. Сервер, который качает вдвое медленнее заявленного
  (заявленное считается не выше 200 Mbps), тоже отменяется. Перед отменой хвост логов
  сервера сохраняется в лог деплоя: вместе с контейнером исчезают и они.
- **Параллельная установка** — галочка «ставить параллельно на все выбранные» (или
  `--race`). Все серверы очереди арендуются сразу, модель ставится на каждом, остаётся
  тот, где она поднялась первой. Отстающие по скорости скачивания (прогноз хуже лидера в
  1,5 раза) отменяются ещё по ходу, но двое лучших держатся до конца — на случай, если
  лидер упадёт на запуске движка. Clore считает аренду поминутно (плюс 0.5 CLORE за
  создание заказа), так что проигравшие стоят минуты. Номера заказов гонки лежат в
  `.env` (`RACE_ORDERS`): если UI упадёт посреди гонки, `python stop.py` отменит все.
  Ctrl+C в окне UI во время гонки сам отменяет её заказы — дождитесь сообщения. Если окно
  закрыть крестиком, отмены не будет: запустите `python stop.py`.
- **Заказ не теряется, даже если деплой оборвался в момент аренды.** Сервер помечается в
  `.env` (`PENDING_SERVER`) ещё до запроса к Clore, и `python stop.py` находит и отменяет
  такой заказ по номеру сервера.
- **SSH-пароль сервера** — случайный на каждый деплой и лежит в `.env` (`SSH_PASSWORD`); в лог он
  не печатается. Если у вас есть публичный ключ (`~/.ssh/id_*.pub`), вход идёт по нему.
- **Имена из чужого репозитория проверяются** перед подстановкой в скрипт сервера: метод
  квантизации, имя GGUF-файла и сам репозиторий с посторонними символами отклоняются.
- **Остановки с сохранением диска нет.** Отмена заказа освобождает сервер и удаляет контейнер
  вместе со скачанными весами — следующий деплой качает модель заново.
- Лимиты API: 1 запрос/с, для создания заказа 1 запрос/5 с — клиент выдерживает паузы сам.

### Старые GPU скрыты не просто так
На Clore много дешёвых 8× Tesla V100 и майнинговых карт. Выглядят выгодно, но:

| Архитектура | Карты | Что с ней не так |
|---|---|---|
| Blackwell / Hopper / Ada | RTX 50xx, H100/H200, RTX 40xx, L40S | всё работает, включая FP8 и FP4 |
| Ampere | A100, A40, RTX 30xx, A6000 | работает; FP8 только через эмуляцию Marlin — медленнее |
| Turing и старее | T4, GTX 16xx, CMP HX, **V100**, P100, M40 | **vLLM с движка V1 требует Ampere** и не стартует; Volta к тому же не умеет bfloat16 и FP8 |

Поэтому список серверов фильтруется по выбранному движку и формату весов: под vLLM и TabbyAPI
карты старее Ampere не показываются, под llama.cpp показываются с пометкой «скорость будет
заметно ниже». Галочка «показывать старые GPU» возвращает их в список — несовместимые
помечаются красным. Архитектура подписана рядом с названием карты.

Хосты с пометкой `Mixed GPUs` не скрываются, но помечаются: модель придётся делить между
разными картами, и движок равняется на слабейшую.

## Файлы
- `app.py` — локальный веб-сервер UI (stdlib, слушает только 127.0.0.1)
- `static/` — сам интерфейс (index.html / app.js / style.css / theme.css / themes.html)
- `clore.py` — клиент REST API Clore.ai (`auth`-заголовок, marketplace / my_orders / create_order / cancel_order / wallets)
- `hfmodels.py` — поиск uncensored-моделей на HF, разбор ссылки, определение формата и оценка VRAM/диска
- `localpc.py` — режим «Мой ПК»: определение железа и оценка, влезет ли модель на этот компьютер
- `localrun.py` — запуск на своём ПК: установка llama.cpp, скачивание и проверка GGUF, изоляция процесса
- `deploy.py` — подбор сервера, аренда, ожидание API, бенч, запись `.env` и переключение OpenCode
- `stop.py` — отмена заказа
- `templates/onstart_*.sh` — startup-скрипты под TabbyAPI / llama.cpp / vLLM (едут в заказ в base64)
- `opencode.sample.json` — образец провайдера для OpenCode. Сам `deploy.py` правит не его,
  а настоящие конфиги OpenCode: вписывает туда `baseURL`, `apiKey` и секцию `models`.
  Главный файл один и тот же на всех системах: `$OPENCODE_CONFIG`, иначе
  `$OPENCODE_CONFIG_DIR/opencode.json`, иначе `$XDG_CONFIG_HOME/opencode/opencode.json`,
  иначе `~/.config/opencode/opencode.json`. **На Windows это тоже `~/.config`, а не
  `%APPDATA%`**: в самом OpenCode путь считается как `XDG_CONFIG_HOME || ~/.config` без
  ветки для Windows, а в `AppData\Roaming\opencode` лежат плагины. Если конфиг положить
  туда, OpenCode его не увидит и модель в списке не появится.
  Остальные найденные копии (в том числе в `%APPDATA%`, `~/opencode.json` и старое имя
  `config.json`) тоже обновляются: конфиги складываются, и забытый провайдер со старым
  адресом может пережить обновление главного.
  Отдельная кнопка «Прописать в OpenCode» на вкладке «Деплой» повторяет запись и
  показывает точный путь — на случай, когда OpenCode поставили уже после деплоя.
  Понимает и `opencode.json`, и `opencode.jsonc` (комментарии при записи теряются —
  об этом пишется в лог). Если конфига нет вообще, создаёт его там, где его ждёт
  OpenCode на этой системе.
  Заодно снимает всё, что прячет провайдера, даже когда он прописан верно:
  убирает `uncensored` из `disabled_providers` и дописывает его в `enabled_providers`
  (этот список, когда задан, включает **только** перечисленных, а остальных игнорирует
  молча). Предупреждает про управляемый конфиг (`%ProgramData%\opencode`, `/etc/opencode`,
  `/Library/Application Support/opencode`): он накладывается поверх пользовательского,
  а прав на запись туда нет.
  Пишется схема v1 (`provider` + `npm` + `options`) — её показывают официальные доки и
  она работает; в схеме v2 тот же блок с полем `npm` молча теряет и `npm`, и `baseURL`.
  Но если конфиг уже переехал на v2, секция `providers` обновляется тоже, в родной для
  неё форме (`package: "aisdk:@ai-sdk/openai-compatible"` + `settings`): иначе в ней
  остался бы прошлый адрес, а при расхождении побеждает именно она
- `ui.sh` / `deploy.sh` / `stop.sh` — запуск под macOS и Linux; `*.bat` — то же под Windows
- `status.sh`, `bench.sh` — состояние заказа и замер скорости
- `sampler.yml` — пресет сэмплинга (temperature 0.7 / top_p 0.95 / min_p 0.02)
- `make_themes.py` — генератор галереи оформления: собирает `static/themes.html`
  (100 вариантов). Палитры строятся из HSL, поэтому внутри варианта фон, панели,
  границы и текст согласованы по тону и контрасту
- `static/themes.html` — галерея; кнопка «Применить» пишет выбранное в `static/theme.css`,
  который подключён поверх `style.css`. Пустой `theme.css` = исходное оформление
- `blacklist.json` — серверы, которые уже показали себя плохо: не ответили за пять минут
  после аренды. В подборе они не появляются,
  очистить можно из UI
- `.env` — ключи и текущий заказ (не публиковать)

Секретов в репозитории нет: шаблоны содержат плейсхолдеры, `deploy.py` подставляет значения из `.env`
в `onstart.generated.sh` (в `.gitignore`), ключи уезжают на сервер через `env` заказа.

## Консоль вместо UI
```
python deploy.py --model owner/name --ctx 65536       # арендовать и развернуть
python deploy.py --dry-run                            # только показать кандидатов
python deploy.py --order-type spot --max-price 0.5            # потолок $0.5/ч
python deploy.py --server 12345                       # конкретный сервер Clore
python deploy.py --server 12345,23456,34567           # очередь: не поднялся первый — берём следующий
python deploy.py --server 12345,23456,34567 --race    # ставить на всех сразу, оставить самый быстрый
python deploy.py --gguf-file model-Q6_K.gguf          # взять не Q4_K_M, а другой квант
python deploy.py --allow-old-gpu                      # не отсеивать карты старее Ampere
python deploy.py --no-opencode                        # не переключать OpenCode на эту модель
python stop.py                                        # отменить заказ из .env
bash status.sh                                        # состояние заказа и API
bash bench.sh                                         # скорость генерации
```

### Несколько деплоев одновременно
По умолчанию состояние живёт в `.env` и `onstart.generated.sh` рядом с проектом, поэтому два
параллельных запуска затирали бы друг другу `ORDER` и `API_URL`. Для одновременных прогонов
задайте каждому свои файлы:

```
UNCENSORED_ENV=runs/a.env UNCENSORED_ONSTART=runs/a.sh python deploy.py --model owner/name --no-opencode
UNCENSORED_ENV=runs/a.env python stop.py        # отмена именно этого заказа
```

## Что пишется в .env после деплоя
`ORDER` (id заказа Clore), `SERVER` (id сервера), `API_URL`, `SSH`, `MODEL_REPO`, `MODEL_NAME`, `CTX`, `ENGINE`.

## Логи на сервере
- `/root/deploy.log` — установка движка
- `/root/download.log` — скачивание весов
- `/root/engine.log` — сам движок; готовность = API отвечает на `/v1/models`

Если в UI долго висит «ждём модель…», зайдите по SSH и посмотрите `deploy.log` — почти всегда
причина видна в первых строках. Четыре грабли, на которые уже наступили и которые обойдены
в `templates/_common.sh`:

| Симптом в логе | Причина | Как обойдено |
|---|---|---|
| `Could not get lock`, затем `pip3: command not found` | Clore при старте контейнера сам ставит пакеты и держит apt | `apt_retry` ждёт блокировку (`DPkg::Lock::Timeout`) и повторяет до 30 раз; `update` и `install` разделены |
| `hf: command not found` бесконечно | скачивание было обёрнуто в `until … do sleep 10; done` | `hf_download` — не больше 40 попыток, потом явная ошибка; `need` падает сразу, если инструмента нет |
| `No CMAKE_CUDA_COMPILER could be found` | onstart запускается не из login-шелла, `/usr/local/cuda/bin` вне `PATH` | PATH и `CUDACXX` выставляются явно |
| `forward compatibility was attempted on non supported HW`, движок на CPU | образ `nvidia/cuda` несёт `/usr/local/cuda/compat` — он работает только на датацентровых картах, на GeForce ломает CUDA | `fix_cuda_compat` убирает слой, если драйвер хоста и так поддерживает нужную CUDA |

Последняя особенно коварна: ошибок в UI нет, API поднимается, но модель считает на CPU —
1.3 токена в секунду вместо 38. Признак — `nvidia-smi` показывает 0% загрузки GPU.

llama.cpp собирается под compute capability конкретной карты (`nvidia-smi --query-gpu=compute_cap`):
сборка под `-arch=native` внутри контейнера не видит GPU и берёт запасную архитектуру.
