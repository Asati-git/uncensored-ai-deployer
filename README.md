# UncensoredAI — любая uncensored-модель с Hugging Face на GPU-сервере Clore.ai

> **In English.** A local, dependency-free UI (Python stdlib only) that rents a GPU server on
> [Clore.ai](https://clore.ai) and deploys any uncensored model from Hugging Face in one click.
> It picks the engine from the weight format (GGUF → llama.cpp, safetensors/AWQ/GPTQ/FP8 → vLLM,
> EXL3/EXL2 → TabbyAPI), estimates VRAM from the model's own `config.json`, finds the cheapest
> suitable server, waits for the build and download with live progress, then exposes an
> OpenAI-compatible endpoint and points OpenCode at it. Bad hosts (silent after five minutes,
> or downloading at less than half the advertised speed) are dropped and blacklisted
> automatically. Runs on Windows, macOS and Linux. The rest of this README is in Russian.

Локальный UI: выбираете расцензуренную модель из подборки Hugging Face (или вставляете свою ссылку),
вводите API-ключ [Clore.ai](https://clore.ai), жмёте «Арендовать и развернуть» — получаете
OpenAI-совместимый endpoint с вашим ключом и переключённый на него OpenCode.

Движок подбирается по формату весов автоматически:

| Формат весов в репозитории | Движок | Docker-образ |
|---|---|---|
| EXL3 / EXL2 | TabbyAPI (ExLlamaV3) | `nvidia/cuda:12.8.1-runtime-ubuntu24.04` |
| GGUF | llama.cpp server (сборка с CUDA) | `nvidia/cuda:12.8.1-devel-ubuntu24.04` |
| safetensors, AWQ, GPTQ, FP8 | vLLM | `nvidia/cuda:12.8.1-runtime-ubuntu24.04` |

Все три отдают один и тот же API: `http://<host>:<port>/v1`, модель называется `uncensored`,
авторизация — `Authorization: Bearer <API_KEY>`.

Вызовы инструментов включены во всех трёх движках: llama.cpp стартует с `--jinja`,
vLLM — с `--tool-call-parser` под семейство модели (`qwen3_coder`, `mistral`, `deepseek_v3`,
`glm45`, `kimi_k2`, иначе `hermes`). Если собранная версия vLLM такого парсера не знает,
startup-скрипт сам откатывается на `hermes`.

## Быстрый старт
1. Запустите UI — откроется http://127.0.0.1:8765. Нужен только Python 3.9+, внешних пакетов нет.

   | система | команда |
   |---|---|
   | Windows | `ui.bat` |
   | macOS, Linux | `./ui.sh` (один раз `chmod +x *.sh`) |
   | любая | `python3 app.py` |

2. Вкладка **Настройки**: вставьте `API-ключ Clore.ai` (кабинет clore.ai → Settings → API),
   нажмите «сгенерировать» для ключа вашего API, при желании добавьте HF-токен и Telegram. «Сохранить».
3. Вкладка **Модель**: подборка актуальных uncensored-моделей (uncensored / abliterated / unfiltered /
   amoral / heretic / dolphin …) с панелью периодов и фильтром по формату, либо своя ссылка —
   `https://huggingface.co/owner/name` или просто `owner/name`. «Выбрать» → UI покажет формат, движок,
   размер весов, оценку нужной VRAM и диска.
4. Вкладка **Сервер**: «Найти серверы» — маркетплейс Clore, уже отфильтрованный под требования модели.
   Можно выбрать конкретный сервер или оставить автоподбор (самый выгодный с учётом скорости канала).
5. Вкладка **Деплой**: «Проверить без аренды» покажет кандидатов, «Арендовать и развернуть» создаёт
   заказ и ведёт лог до строки «модель готова».

Подъём с нуля: 10–40 мин (в основном скачивание весов; для GGUF плюс сборка llama.cpp).

### Откуда берётся «нужно VRAM»
`веса выбранного кванта + KV-кэш под контекст + буферы движка (1.5 ГиБ + 2% весов, не больше 8)`.

KV-кэш считается не на глаз, а по `config.json` модели — своего у GGUF-репозитория нет,
поэтому он берётся у исходной модели из `base_model`. Наивная формула «слои × головы ×
head_dim» на современных архитектурах завышает в разы, и учитываются две поправки:

- **MLA** (`kv_lora_rank`, как у DeepSeek и GLM-5) — в кэш идёт сжатое латентное
  представление, а не полные K и V;
- **гибридное внимание** (`layer_types`) — у линейных слоёв состояние постоянное
  и от длины контекста не растёт.

Для GLM-5.3 Flash разница наглядная: по наивной формуле выходило 22.5 ГиБ KV, по факту — 0.2 ГиБ.
Если `config.json` недоступен (базовый репозиторий удалили), KV прикидывается по числу
параметров, и в карточке это подписано как «оценка».

llama.cpp запускается с кэшем в `q8_0` — это вдвое меньше fp16 при практически той же
точности; vLLM оставлен в fp16.

### «★ Топ для кодинга»
Первая кнопка на панели — не рейтинг Hugging Face, а ручная подборка расцензуренных моделей,
которые реально пишут код. Список лежит в `hfmodels.TOP_CODING`, счётчики скачиваний и дата
обновления подтягиваются с HF в момент открытия; удалённые или переименованные репозитории
молча выпадают.

**Одна карточка = одно семейство** (Qwen, GLM, Mistral, DeepSeek). Внутри — его модели:
рекомендуемая раскрыта, остальные свёрнуты. У каждой модели перечислены форматы весов,
в которых её выложили, — сначала выбирают модель, формат уже под конкретный сервер.
Фильтр по формату отсекает варианты; модели и семейства, у которых не осталось ни одного,
пропадают целиком.

Конкретный квант GGUF выбирается **после** «Выбрать» — в карточке модели наверху вкладки.
Там же показаны размер каждого кванта и пересчитанные под него требования к VRAM и диску.

В список попадают только кванты **Q4_K_M и выше** — ниже код начинает сыпаться, и держать
такие варианты незачем; сколько скрыто, написано под выпадающим списком. Отсекаются ещё две
категории мусора: служебные файлы (`mmproj`, `imatrix`, LoRA, патчи) и draft-модели для
спекулятивного декодирования — последние по арифметике «размер ÷ бит на вес», без списка имён.
Если в репозитории нет ни одного кванта от Q4_K_M, показывается что есть с предупреждением —
иначе модель стало бы невозможно развернуть.

У каждой записи указана **базовая модель и дата её выхода** — по названию репозитория это
не читается, а разница принципиальная: три верхних пункта выглядят как «одна и та же Qwen»,
но стоят на базах 2026-08, 2026-01 и 2025-07.

| Семейство | Модели внутри |
|---|---|
| **Qwen** — основной выбор | **Qwen3.8-27B NEO-CODER-MAX** (база 2026-08, Q4_K_M 16.8 ГиБ) — рекомендуем; Qwen3-Coder-Next (база 2026-01, Q4_K_M 45 ГиБ) — потолок качества; Qwen3.8-27B Coder390 EfficientThink — reasoning; Qwen3-Coder-30B-A3B (база 2025-07) — быстрая и дешёвая; Qwen3.6-27B Coder MXFP8 — дешёвый vLLM; Qwen2.5-Coder-14B (Q4_K_M 8.4 ГиБ) — дешёвый вход; Qwen2.5-Coder-32B — классика |
| **GLM** — универсал | GLM-5.3 Flash: не кодер по профилю, но пишет код на уровне топовых и держит длинный диалог. Расцензуренная сборка только в XL-квантах: Q4_K_XL 186 ГиБ |
| **Mistral / Devstral** — агентный | Devstral Small 2 24B: 65.8% SWE-bench Verified при 24B, плотная — предсказуема на длинных правках |
| **DeepSeek** — только мультиGPU | **DeepSeek V4.1 Flash** (база 2026-10): Q4_K_M 397 ГиБ, FP8 475 ГиБ — минимум 8 карт по 80 ГБ; **V4 Flash 0731**: Q4_K 153 ГиБ, 4 карты по 48 ГБ — подъёмный вариант, если нужен именно DeepSeek |

Правило по квантам для кода: **не ниже Q4_K_M**. Ниже заметно падает точность генерации —
модель начинает терять скобки и отступы, и сэкономленные гигабайты обходятся дороже.
Этот же порядок зашит в выбор кванта по умолчанию (`_QUANT_RANK` в `hfmodels.py`): берётся
Q4_K_M, а при одинаковом имени — файл покрупнее, чтобы не подхватить draft-модель.

Подборку правьте прямо в `TOP_CODING` — UI подхватит после перезапуска `app.py`.

### Панель периодов на вкладке «Модель»
| Кнопка | Чем сортирует | Точность |
|---|---|---|
| За всё время | `downloadsAllTime` (сортировка на нашей стороне — HF не принимает такой `sort`) | точный счётчик |
| За месяц | `downloads` — счётчик Hugging Face за 30 дней | точный счётчик |
| За неделю | `trendingScore` среди моделей, обновлённых за 7 дней | приближение |
| За день | `trendingScore` среди моделей, обновлённых за 2 дня | приближение |
| Новые | `lastModified` | точно |

Недельных и дневных счётчиков скачиваний Hugging Face не публикует, поэтому «за неделю» и «за день» —
это рейтинг тренда HF среди свежих репозиториев; в UI это подписано под панелью.

## Важно про Clore.ai
- **Все цены в UI — в долларах за час.** Сам Clore публикует их за сутки и в трёх валютах
  (USDC / BTC / CLORE), поэтому UI пересчитывает: берёт USD-цену хоста (`price.original_usd`),
  а если её нет — конвертирует по курсам `currency_rates_in_usd`, и делит на 24.
- Валюта списания выбирается автоматически: самая дешёвая по курсу из тех, на которых есть средства.
  Принудительно задать можно флагом `--currency bitcoin|CLORE-Blockchain|USD-Blockchain`.
- Баланс и адреса депозита — вкладка **Заказы**.
- Типы заказа: `on-demand` (стабильно) и `spot` (дешевле, но ваш заказ могут перебить ставкой).
- **Остановки с сохранением диска нет.** Отмена заказа освобождает сервер и удаляет контейнер
  вместе со скачанными весами — следующий деплой качает модель заново.
- Лимиты API: 1 запрос/с, для создания заказа 1 запрос/5 с — клиент выдерживает паузы сам.

### Старые GPU скрыты не просто так
На Clore много дешёвых 8× Tesla V100 и майнинговых карт. Выглядят выгодно, но:

| Архитектура | Карты | Что с ней не так |
|---|---|---|
| Blackwell / Hopper / Ada | RTX 50xx, H100/H200, RTX 40xx, L40S | всё работает, включая FP8 и FP4 |
| Ampere | A100, A40, RTX 30xx, A6000 | работает; FP8 только через эмуляцию Marlin — медленнее |
| Turing и старее | T4, GTX 16xx, CMP HX, **V100**, P100, M40 | **vLLM с движка V1 требует Ampere** и не стартует; Volta к тому же не умеет bfloat16 и FP8 |

Поэтому список серверов фильтруется по выбранному движку и формату весов: под vLLM и TabbyAPI
карты старее Ampere не показываются, под llama.cpp показываются с пометкой «скорость будет
заметно ниже». Галочка «показывать старые GPU» возвращает их в список — несовместимые
помечаются красным. Архитектура подписана рядом с названием карты.

Хосты с пометкой `Mixed GPUs` не скрываются, но помечаются: модель придётся делить между
разными картами, и движок равняется на слабейшую.

## Файлы
- `app.py` — локальный веб-сервер UI (stdlib, слушает только 127.0.0.1)
- `static/` — сам интерфейс (index.html / app.js / style.css / theme.css / themes.html)
- `clore.py` — клиент REST API Clore.ai (`auth`-заголовок, marketplace / my_orders / create_order / cancel_order / wallets)
- `hfmodels.py` — поиск uncensored-моделей на HF, разбор ссылки, определение формата и оценка VRAM/диска
- `deploy.py` — подбор сервера, аренда, ожидание API, бенч, запись `.env` и переключение OpenCode
- `stop.py` — отмена заказа
- `templates/onstart_*.sh` — startup-скрипты под TabbyAPI / llama.cpp / vLLM (едут в заказ в base64)
- `opencode.sample.json` — образец провайдера для OpenCode. Сам `deploy.py` правит не его,
  а настоящие конфиги OpenCode: вписывает туда `baseURL`, `apiKey` и секцию `models`.
  Ищет во всех местах, которые описаны в документации OpenCode, и обновляет **все**
  найденные — конфиги там не заменяют друг друга, а складываются, поэтому забытый
  провайдер со старым адресом в соседнем файле может пережить обновление главного:
  `$OPENCODE_CONFIG` → `$OPENCODE_CONFIG_DIR` → `$XDG_CONFIG_HOME/opencode/` →
  `~/.config/opencode/` → `~/Library/Application Support/opencode/` (macOS) →
  `%APPDATA%\opencode\`, `%LOCALAPPDATA%\opencode\` (Windows).
  Понимает и `opencode.json`, и `opencode.jsonc` (комментарии при записи теряются —
  об этом пишется в лог). Если конфига нет вообще, создаёт его там, где его ждёт
  OpenCode на этой системе
- `ui.sh` / `deploy.sh` / `stop.sh` — запуск под macOS и Linux; `*.bat` — то же под Windows
- `status.sh`, `bench.sh` — состояние заказа и замер скорости
- `sampler.yml` — пресет сэмплинга (temperature 0.7 / top_p 0.95 / min_p 0.02)
- `make_themes.py` — генератор галереи оформления: собирает `static/themes.html`
  (100 вариантов). Палитры строятся из HSL, поэтому внутри варианта фон, панели,
  границы и текст согласованы по тону и контрасту
- `static/themes.html` — галерея; кнопка «Применить» пишет выбранное в `static/theme.css`,
  который подключён поверх `style.css`. Пустой `theme.css` = исходное оформление
- `blacklist.json` — серверы, которые уже показали себя плохо: не ответили за пять минут
  после аренды или качали вдвое медленнее заявленного. В подборе они не появляются,
  очистить можно из UI
- `.env` — ключи и текущий заказ (не публиковать)

Секретов в репозитории нет: шаблоны содержат плейсхолдеры, `deploy.py` подставляет значения из `.env`
в `onstart.generated.sh` (в `.gitignore`), ключи уезжают на сервер через `env` заказа.

## Консоль вместо UI
```
python deploy.py --model owner/name --ctx 65536       # арендовать и развернуть
python deploy.py --dry-run                            # только показать кандидатов
python deploy.py --order-type spot --max-price 0.5            # потолок $0.5/ч
python deploy.py --server 12345                       # конкретный сервер Clore
python deploy.py --gguf-file model-Q6_K.gguf          # взять не Q4_K_M, а другой квант
python deploy.py --allow-old-gpu                      # не отсеивать карты старее Ampere
python deploy.py --no-opencode                        # не переключать OpenCode на эту модель
python stop.py                                        # отменить заказ из .env
bash status.sh                                        # состояние заказа и API
bash bench.sh                                         # скорость генерации
```

### Несколько деплоев одновременно
По умолчанию состояние живёт в `.env` и `onstart.generated.sh` рядом с проектом, поэтому два
параллельных запуска затирали бы друг другу `ORDER` и `API_URL`. Для одновременных прогонов
задайте каждому свои файлы:

```
UNCENSORED_ENV=runs/a.env UNCENSORED_ONSTART=runs/a.sh python deploy.py --model owner/name --no-opencode
UNCENSORED_ENV=runs/a.env python stop.py        # отмена именно этого заказа
```

## Что пишется в .env после деплоя
`ORDER` (id заказа Clore), `SERVER` (id сервера), `API_URL`, `SSH`, `MODEL_REPO`, `MODEL_NAME`, `CTX`, `ENGINE`.

## Логи на сервере
- `/root/deploy.log` — установка движка
- `/root/download.log` — скачивание весов
- `/root/engine.log` — сам движок; готовность = API отвечает на `/v1/models`

Если в UI долго висит «ждём модель…», зайдите по SSH и посмотрите `deploy.log` — почти всегда
причина видна в первых строках. Четыре грабли, на которые уже наступили и которые обойдены
в `templates/_common.sh`:

| Симптом в логе | Причина | Как обойдено |
|---|---|---|
| `Could not get lock`, затем `pip3: command not found` | Clore при старте контейнера сам ставит пакеты и держит apt | `apt_retry` ждёт блокировку (`DPkg::Lock::Timeout`) и повторяет до 30 раз; `update` и `install` разделены |
| `hf: command not found` бесконечно | скачивание было обёрнуто в `until … do sleep 10; done` | `hf_download` — не больше 40 попыток, потом явная ошибка; `need` падает сразу, если инструмента нет |
| `No CMAKE_CUDA_COMPILER could be found` | onstart запускается не из login-шелла, `/usr/local/cuda/bin` вне `PATH` | PATH и `CUDACXX` выставляются явно |
| `forward compatibility was attempted on non supported HW`, движок на CPU | образ `nvidia/cuda` несёт `/usr/local/cuda/compat` — он работает только на датацентровых картах, на GeForce ломает CUDA | `fix_cuda_compat` убирает слой, если драйвер хоста и так поддерживает нужную CUDA |

Последняя особенно коварна: ошибок в UI нет, API поднимается, но модель считает на CPU —
1.3 токена в секунду вместо 38. Признак — `nvidia-smi` показывает 0% загрузки GPU.

llama.cpp собирается под compute capability конкретной карты (`nvidia-smi --query-gpu=compute_cap`):
сборка под `-arch=native` внутри контейнера не видит GPU и берёт запасную архитектуру.

## Проверка API
```
curl $API_URL/models -H "Authorization: Bearer $API_KEY"
```

Туннель вместо открытого порта: `ssh -p <PORT> root@<HOST> -L 5000:localhost:5000 -N`
→ baseURL `http://localhost:5000/v1`
